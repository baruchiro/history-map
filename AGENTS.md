## Start here
1. Read [backlog](project/BACKLOG.md) and [decisions](project/DECISIONS.md). Check current issues, pull requests and the default branch before starting duplicate work.
2. Pick one bounded task, state acceptance criteria and affected files. Use your own branch/worktree or fork. This document grants no account access, publishing permission or spending authority.
3. Read [query stories](stories/README.md) for product intent. Read [CONTRIBUTING.md](CONTRIBUTING.md) and [SKILL.md](SKILL.md) before event-list work.
4. Run the checks in [validation](principles/validation.md). Report what changed, evidence, limitations and next step in the PR or handoff. An agent's confident summary is not proof.

Default branch is currently `master`; verify it before using commands copied from other projects. Preserve other contributors' work. Ask the maintainer only about unresolved product conflicts, authority gaps or hard-to-reverse changes; continue independent research and local tests while waiting.
